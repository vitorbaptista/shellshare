Last updated: August 21, 2026. This page describes the data behavior implemented by Shellshare and the hosted shellshare.net service. A separately operated, self-hosted Shellshare server can use different infrastructure and retention settings, so its operator is responsible for documenting those choices.

Shellshare broadcasts terminal output one way, from the broadcaster to read-only viewers. Broadcasts are end-to-end encrypted by default. Encryption happens in the CLI before output is sent, and decryption happens in the viewer. The key is the part of the share URL after #; URL fragments are not sent to the server. The hosted relay stores and forwards encrypted records, not readable terminal text, unless the broadcaster explicitly uses --disable-encryption.

Shellshare does not require user accounts. The server keeps recent room history so someone joining late or reconnecting can see the current terminal state. On shellshare.net, a room and its recent history are removed after the room has been idle for six hours. Reads do not extend that window. Reusing the same named room starts a fresh session and clears the previous run’s stored output. The embedded shellshare serve mode keeps data only in that local server process.

The server software supports optional PostHog usage analytics, disabled unless an operator configures both an API key and a private salt. When enabled, events describe broadcasts starting and ending, durations, room names, viewer joins, and viewer counts. Broadcasters receive a pseudonymous identifier produced by HMAC-SHA256 from the operator’s private salt and the room password. Viewer identifiers are random for each join. Shellshare does not send terminal contents, room passwords, decryption keys, or visitor IP addresses to PostHog, and GeoIP enrichment and person profiles are disabled in those events.

Room names, timing, connection metadata, and traffic volume are not hidden by encryption, and infrastructure providers process connection information such as IP addresses to deliver the service. Anyone with the complete share link can watch, so do not broadcast secrets. The implementation is public in the source repository; privacy questions can use the contact page.
