Agent and script API

shellshare exec --json -- npm test

Shellshare’s supported automation API is its command-line JSON stream. exec runs a command in a PTY, broadcasts it, and exits with the command’s exit code. With --json, the first newline-delimited JSON event contains "event":"sharing" and the complete share url; the last contains "event":"end" and exit_code. Errors stay on stderr. Pipes work too: tail -f build.log | shellshare --json.

WebSocket API and authentication

Viewers can fetch GET /r/<room>.bin for a snapshot or connect to WebSocket /ws/v/r/<room> for history followed by live frames. The official CLI broadcasts through WebSocket /ws/r/<room>, authenticating with the room secret in the HTTP Authorization header. Binary frames carry terminal bytes or encrypted records; text frames carry control JSON. There are no accounts, OAuth flow, bearer API keys, or role scopes. The encryption key after # in a viewer URL is never sent to the server.

OpenAPI, webhooks, and MCP

Shellshare has no OpenAPI specification, webhook product, or MCP server because its supported interface is the streaming CLI and WebSocket protocol above. Agents should use shellshare exec --json and the reader in llms.txt. Source, self-hosting instructions, and the complete protocol are in the Shellshare repository.
